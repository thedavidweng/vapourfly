# GUI information architecture and design system

The Vapourfly desktop GUI is a GPUI + [gpui-component](https://github.com/longbridge/gpui-component) application. It is built from gpui-component's standard components (TitleBar, segmented TabBar, Popover, dropdown and context menus, Select, Dialog, Sheet, Notification, Switch, Tag, DescriptionList, Empty, Skeleton) rather than hand-drawn widgets, so focus, keyboard and hover behavior come from the toolkit. Icons are the bundled Lucide set. Where a component only needs a different size or colour, it is restyled rather than replaced: the hero's Play, Details and More like this are stock `Button`s with a custom variant and a 48px height, and clickable list rows are `ListItem`s. Only three things are drawn directly. The navigation sidebar is hand-drawn because `SidebarMenuItem` fixes its row at 28px and is not a tab stop. The Library hero and the cover capsules are hand-drawn because no component covers them. Rows and capsules outside a `List` are given a tab stop by hand, because they would otherwise not be reachable by keyboard.

The visual reference is SteamOS (Steam Big Picture and the Steam Deck UI), adapted to a desktop window: dark slate surfaces, Steam blue (`#1a9fff`) for selection and primary actions, and Steam green reserved for Play. There is no violet or indigo accent. Colour values come from the Steam client's own stylesheet where it has one:
- `#3d4450` for a focused field row.
- `#464d58` and `#393f49` for button hover and press.
- `#dcdedf` and `#8b929a` for secondary and muted text.
- `#47bfff` for primary hover.
- `#de3618` for destructive fills.
- The GreenPlay gradient, `rgb(138,195,41)` to `rgb(74,122,22)`.

Corners are nearly square (2–4px), as in SteamOS. Valve's desktop rule is that pointer hover looks the same as controller focus, and Vapourfly follows it so the app behaves the same with a mouse, a keyboard, or Steam Input on a Deck:
- Rows and sidebar items show one fill for both hover and keyboard focus. The sidebar's hover/focus band is brighter than the band that marks the current page.
- Capsules show a white ring on hover and on focus.
- Every interactive element is a tab stop that Enter and Space activate. In dark mode the toolkit focus ring is white, the gamepad UI's focus colour.

Game controllers are read directly (gilrs) rather than relying on Steam Input's keyboard emulation, so a Deck works in Desktop Mode and with any Xbox-style pad. The controller drives the same focus model as the keyboard: the D-pad moves focus by synthesizing arrow and Tab key events, A and B send Enter and Escape, so popovers, menus, dialogs and sheets keep their own toolkit navigation and focus traps. The sidebar is its own focus zone: Up / Down move through it without switching page, and A or Right opens the page. LB / RB cycle pages. The Library grid, shelf and list have a two-dimensional cursor that scrolls the virtualized list to reveal the focused card. The right stick scrolls the page and the triggers page through it. On SteamOS, text fields call up Steam's on-screen keyboard. A footer of button hints is shown only while the controller is the last input. On a Steam Deck in Game Mode the window opens fullscreen at the Deck's 1280×800 and the Library hero shrinks with the window height. Text and controls are sized for normal screens at normal viewing distance: the root font size is 16px, so every rem-based spacing and control height scales with it, page titles are 32px, section headings 19px, body text 15px and captions 13px. The shell is a 260px sidebar (68px when collapsed) and a title bar on a darker `surface`, with the active page set flush beside it on a lighter `canvas` panel, as in SteamOS. The sidebar is headed by the signed-in Steam profile rather than the app name: the avatar from Steam's local `config/avatarcache/<SteamID64>.png` (initials on Steam blue when there is none), the persona name and the login name. The account is the configured one, else Steam's most recent login. The current destination is marked with a full-width band, and divider lines separate the groups. Dark mode is the primary look and the default when no preference has been saved; light mode is a cool-grey counterpart with the same layout. Native OS window controls remain authoritative; the app does not draw its own traffic-light circles. Theme mode is toggled from the title bar and Settings → Appearance, and persists across launches in a GUI-only file (`gui-theme` under the platform data directory), not domain config.

The unfiltered Library opens on a full-width "continue playing" hero for the most recently played game (hero art, logo, Play / Details / More like this), then a Recently played shelf, then the full grid of 600×900 portrait capsules. Searching, filtering or changing scope hides the hero and shelf. Play hands off to Steam with `steam://rungameid/<id>`, or `steam://install/<id>` for games that are not installed.

Steam artwork (header, portrait capsule, hero and logo) is read from Steam's local `appcache/librarycache` first, then from Vapourfly's cache, and is downloaded in the background when missing (never in demo or offline mode). Games without art get a generated duotone cover, so layout never depends on the network. Status and errors appear as toast notifications; Steam writes and restores are confirmed in a modal dialog that previews the change; game details open in a side sheet.

Sidebar destinations are grouped, without headings: **Play** (Library, Discover, Recommendations), **Organize** (Playlists, Collections) and **System** (Data Sources, Settings). Library is the default landing view. Discover is a first-class destination. Junk cleanup is a Library workflow opened from the Library header, with mode, preview, collection, and hide actions. Backups and restore live under Settings. Domain concepts and safety behavior remain unchanged: Playlist and Steam Collection stay distinct, every Steam write stays confirmation-gated, and hydration follows ADR-0009.
